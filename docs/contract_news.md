# 自由契約・契約動向

## 選手動向表

トップの直接リンク「選手動向一覧」、または「成績」メニューから開けます。
`scraper/player_movements.py` がスポナビの公開入退団表を読み、`data/player_movements.json` に保存します。
同じ2時間ごとのworkflowで取得・公開します。手動実行は `python scraper/player_movements.py`。

- 1行は掲載球団・選手・更新日・状況・備考の組み合わせ。同一行は重複排除。
- ニュースの見出しから個人の契約状態を推定しません。正式発表の認定も行いません。
- 日付はスポナビ更新日。所属欄の球団であり、現時点の契約先とは限りません。
- FA権取得、FA宣言、FA移籍を別区分にし、単にFAとある場合は区分未確認とします。
- 移籍先は「○○へ移籍」「移籍先：○○」等の明示がある場合のみ抽出。なければ記載なし。
- 12球団の欄と列定義を検証。構造変更や取得失敗時は前回ファイルを保持。
- 現掲載分のスナップショットです。過去の全履歴を保証しません。以前の年の掲載分も更新年で絞り込めます。
- 原文はsource_noteに保持し、画面では「戦力外」を「来季契約なし」と表記します。
- 関連ニュースは表とは別に折りたたみ表示します。

トップの「成績」→「自由契約・契約動向」から `contract_news.html` に移動します。
スポーツナビの公開ニュース一覧を検索し、2026-09-28以降の配信見出し、媒体名、配信日時、元記事URLを保存します。

## 更新

```sh
python scraper/contract_news.py
python -m unittest tests.test_contract_news -v
```

出力: `data/contract_news.json`。既存の記事はURLで重複排除しながら蓄積します。
`--since YYYY-MM-DD`、`--until YYYY-MM-DD`、`--pages 1〜10`、`--output PATH`で変更できます。
検索語ごとに既定5ページまで。取得上限に達した場合は画面にも表示します。
取得失敗・HTML構造変更の場合は終了コード非ゼロとし、前回のJSONを保持します。

`.github/workflows/contract_news.yml` は9〜12月の2時間ごとと手動実行に対応します。
mainへの反映前には定期実行されません。既存のデータ書込ジョブと同じ concurrency group を利用します。
取得・保存の成功後にGitHub Pagesの再ビルドを明示的に要求します。Actionsによるコミットだけでは公開が更新されないためです。

## 読み方・限界

- 表示名は「自由契約・契約動向」。通常表示は中立的な記事カテゴリと名鑑で確認できた見出し内の選手名です。
- 原見出しは変更せず保持し、展開時にのみ表示します。
- これはニュース索引です。掲載記事から選手の正式な契約状態を自動更新しません。
- 球団フィルターは見出しの文字一致。元所属先が言及される場合もあるため現所属の確定には使いません。
- 名前は既存名鑑とのフルネーム一致のみ。表記揺れ、姓のみ、育成選手などは一致しないことがあります。
- 明示的な独立リーグ・MLBの記事は除外。回顧・コメントと判別できた記事は初期表示から外し、選択で表示できます。
- 本文にしか契約情報がない記事、検索一覧から消えた記事は取得できない場合があります。
- 記事本文と写真は収集・転載しません。元記事、入退団一覧、NPB公示へのリンクで確認できます。
