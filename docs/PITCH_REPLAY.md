## 実データと簡易モデルの境界

画面に常時表示:

> 実際の投球軌道を完全再現したものではなく、収集データをもとにした簡易再現です

- **保存値**: 球種・球速・元のcourse・投球結果・選手・回・打席結果。欠損値は未取得とする。
- **座標の変換**: 既存 `index.html::buildChart` の投手視点という定義に合わせ、`x = 1 - left_px / 63`、`y = top_px / 63` とする。既存のゾーン目安 `left=5, right=50, top=10, bottom=58` も同時に反転する。座標の向きはリポジトリの既存仕様に依拠しており、計測器で検証した3D座標ではない。
- **コースの言葉**: 保存labelは左右打者の区別をしていないため、そのまま内外角の事実として再利用しない。座標と打者の左右から変換し、元の保存labelも別に表示する。打者の左右が不明・両打の場合は「捕手視点の左/右」。
- **毎球のB/S**: 完全な球順と識別可能な結果からの再計算。ファウルは2ストライク止まり。欠番・結果不明の後は未取得とする。
- **アウト数**: `count.out` を「O（取得時点・固定）」と表示する。打席終了に伴うアウト増加、盗塁死などを推測で作らない。
- **countの出典制約**: 収集パーサーは公式sboを優先し、なければB/Sを推定するが、その出典フラグと取得タイミングを保存していない。したがって `recordedCount` を「公式の投球前カウント」とは表現しない。
- **取得できないため簡易モデルで補完**: リリース位置・球種軌道・変化量・見やすさを優先した飛行時間。グリッドしかない場合の着弾セル中心。投手の左右が不明なら横変化を加えない。コースそのものがない球は軌道も着弾も描かない。
- **AIによる解釈**: 未接続。投手の意図や配球の狙いを実データとして生成しない。

表示用の変化量は `trajectory()` 内に閉じ込め、AI向けの観測値へ混ぜない。ナックル等の未分類球種はニュートラル軌道。同一コースが重なる場合は番号ラベルだけを移動し、元の記録位置との接続線を残す。画面外の座標をストライクゾーンへ押し込めない。

## 実装した機能

- 日付・試合・打席を選択し、1球ずつまたは打席全体を再生。
- 軽量SVGによる捕手視点の3×3ゾーン、奥から手前へ大きくなるボール、球種別軌道・色、球順の着弾ラベル。
- 捕手視点／打者視点の切り替え。打者の左右に応じた簡易の目線・遠近変換を、球・ゾーン・着弾点に共通適用。再生途中でも位置を切り替えられ、保存値と再生進行は変わらない。打者の左右不明時は打者視点を無効にする。
- 右打ち・左打ちに対応した共通SVG打者イラスト。捕手視点では打者の全身、打者視点では手元とバット。画像の表示切り替えあり。実在選手の容姿・固有フォームの再現ではないことを明記。
- 現在の球種の動きを説明する表示（例: フォーク「ホーム付近で下に落ちる」）。実測変化量や投球意図とは分離。
- 球速に応じた800〜2,100msの表示用時間。未取得時は共通1,400ms。0.5x / 1x / 1.5x / 2x。
- 再生、一時停止/再開、前後の球選択、最初から再生。表からの選択。最終球後に打席結果を表示。
- PCは左にアニメーション・操作、右に投球情報。900px以下は縦並び。横に長い投球一覧は内部スクロール。
- キーボードで操作可能なボタンとフォーム、現在行の `aria-current`、状態通知。動きを減らす設定では飛行を省略し、着弾と情報だけ更新。非表示タブに移ると一時停止。
- 試合詳細の各打席に「この打席をリプレイ」。ANALYST LAB「配球」から選択投手の打席へ移動し、可能なら直近登板も引き継ぐ。該当打席がなければ日付変更または絞り込み解除を案内。
- 最大8件のJSONキャッシュ。日付/試合変更時に旧リクエストを中止し、古い応答で選択を上書きしない。
- JSON保存と `getPlateAppearanceSummary()`。選択した打席をURLへ反映し、同じURLで再表示可能。

未実装: 実測の投球軌道・回転数・変化量・リリース点の再現、毎球の実測カウント/アウトの復元、GPT等のAPI接続。いずれも今回の保存データにない値を捏造しないため、または今回任意の将来機能であるため。

## AI / NPB Chatの拡張ポイント

ブラウザで `window.getPlateAppearanceSummary()` を呼ぶと現在選択している打席のJSONを返す（読み込み中は `null`）。モデル単体では `PitchReplay.getPlateAppearanceSummary(pa)` を使用する。

主なフィールド:

- `schemaVersion`, `plateAppearanceId`, `source.file / gameId / index / arrayIndex`
- `pitcher`, `batter`, `date`, `inning`, `topBottom`, `recordedCount`, `result`
- `pitches[]`: 保存球順、球種、球速、元のcourse、投球結果、および `derived.countBefore / countAfter`
- `provenance`: 保存値・導出値・簡易モデルの制約。
- `aiInterpretation: null`: 将来の解釈を観測事実から分離する欄。

NPB Chat等へはこのJSONを入力とし、解説出力を別パネルへ表示する。実装時は未取得値を推測で埋めないこと、投球意図は「可能性」として述べることを入力ルールに含める。API認証を要する接続はサーバー側で扱い、公開静的ファイルへ秘密鍵を保存しない。

## ローカル確認

リポジトリのルートでHTTPサーバーを起動する（`file://` での直接起動はfetchが動かない）。

```sh
python -m http.server 8000 --bind 127.0.0.1
```

`http://127.0.0.1:8000/pitch_replay.html` を開く。

実データの直接リンク例:

```text
http://127.0.0.1:8000/pitch_replay.html?game=data%2F2026%2F03%2F27%2F2021038622.json&atbat=0110200
```

再生UI: 「1球ずつ」では着弾後に停止し、再生を押すと次球へ。「連続」では短い間隔を置いて次球へ。前後ボタン・一覧は選択球の再生前に移動し、一時停止状態となる。「最初から」は初球からすぐ再生する。最後まで再生した後の再生ボタンも初球に戻る。
